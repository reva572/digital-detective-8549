# Task 6.1 — Git workflow

- git status — Checks the current state of the repository and shows modified or staged files.
- git add — Stages selected changes for the next commit.
- git commit — Saves staged changes as a checkpoint in Git history.
- git log --oneline -5 — Displays the five most recent commits in a compact format.


My understanding:
Git tracks changes made to files in a project. Staging selects which changes should be included in a commit, while committing saves those changes in the repository's history. Git history helps us review previous work

# Task 6.4 — Git Command Glossary

1. `git init` — Initializes a new Git repository.
2. `git status` — Shows the current state of the working directory.
3. `git add` — Stages selected changes for a commit.
4. `git commit` — Saves staged changes as a commit.
5. `git log` — Displays the commit history.
6. `git branch` — Lists existing branches.
7. `git branch branch-name` — Creates a new branch.
8. `git switch branch-name` — Switches to another branch.
9. `git push` — Publishes local commits to a remote repository.
10. `git pull` — Fetches and integrates changes from a remote repository.

My understanding:
Git helps track changes in a project. Staging selects changes for the next commit, while committing saves those changes in the repository. Branches allow independent development, and Pull Requests help review and merge changes collaboratively
